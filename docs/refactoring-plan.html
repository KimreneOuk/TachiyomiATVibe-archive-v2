Target architecture

The spines stay; the noise around them goes. After all stages:

  • Engines — one authoritative implementation per capability: OCR (PageRecognitionEngine→RoiPageRecognitionEngine, split into pipeline/factory/grouping stages), inpaint (PageInpaintingEngine + split Coordinator), colorize (2 live engines, shared preprocessor/combine — already unified), translate (Base/AiTranslator hierarchy, verified clean), render (FontFittingAlgorithms as the only fit/wrap authority, cycle broken).
  • Pipeline — coordinators slimmed with a shared join protocol; batch executor named honestly (ChapterBatchExecutor); progress has exactly one live representation; no unwired planners.
  • Persistence — ChapterArtifactEngine as the hub with its candidate/rekey/retention collaborators; PublicationBridge kept (4 clients); verified-write lives in persistence; store facade without dead forwarders.
  • Runtime — ModelDeployment owns asset integrity+copy; QnnContextCacheManager owns the staged protocol behind one generalized Plan; one memory-facts owner (EngineMemoryBudget).
  • Diagnostics — one light spine (TelemetryTrace) + one condensed structured emitter (~500L) with the privacy pseudonymizer preserved verbatim; legacy facades kept for 23 UI call sites.
  • Domain — enums/prefs/state only; pools moved to app processing/memory/; dead credential/validator files gone.

Estimated net effect (transparent math, per critical review): S1 −420 · S2 −4,900…−5,300 · S3 −900 · S4 −2,215 (diagnostics condense −2,125 + memory facts −90; splits themselves Δ0) · S5 −150…−200 ⇒ net ≈ −8,000 ± 500 production lines (~13%), of which ~2,100 is the condense — if the condense is deferred, the remainder is ≈ −5,900. Files: −32 to −42 (26 deletions + ~14 merge absorptions, minus a handful of new seam files). Target ≈ 52–53k lines in ~240 files with every file's purpose defensible in one sentence. Zero behavior change except the gated D2 fix.
